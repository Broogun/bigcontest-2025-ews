> 가천대학교 응용통계학과 — 김영민 · 박형건 · 오휘연 · 한민규

## 배경 및 문제 정의

서울 성동구의 영세·중소 요식 가맹점은 매년 상당수가 폐업을 경험하지만, 대부분의 자영업자는 위기가 심화된 이후에야 이를 인식합니다. 폐업 직전 수개월간 카드거래 데이터에는 이미 **매출 급락, 거래 건수 감소, 고객 이탈** 등의 선행 신호가 나타나지만, 개인의 경험만으로는 이를 조기에 포착하기 어렵습니다.

기존 접근법의 한계:
- **이진 분류 모델**: 폐업(1) vs 생존(0)으로 단순화 → 클래스 극심한 불균형, 확률값 해석 어려움
- **정적 특성 활용**: 점포 속성(업종·위치) 위주 → 시간에 따른 경영 악화 신호 미반영
- **정보 누수**: 폐업 시점 전후 데이터를 혼용해 AUC를 과대평가하는 구조적 문제

---

## 핵심 접근법: 순위 기반 조기경보 시스템

전통적 이진 분류 대신 **"지금 얼마나 위험한가"를 동종 업종·상권 내 상대적 순위(백분위)로 표현**합니다.

```
이진 분류 모델         순위 기반 EWS
─────────────────    ──────────────────────────────────
폐업 확률: 32.7%  →  업종 내 위험 순위: 상위 12% (위험 등급)
폐업 확률: 31.9%  →  업종 내 위험 순위: 상위 54% (주의 등급)
```

동일한 수치도 **동종 대비 맥락** 속에서 해석돼야 의미 있습니다.

## 방법론

### 1. 시간 정렬 및 정보 누수 방지

| 기법 | 설명 |
|------|------|
| **사건 정렬 (Event Alignment)** | 폐업 직전 8개월을 T-8 → T-0으로 정렬해 폐업 궤적 분석 |
| **Alive Baseline** | 순위 산출 기준을 현재 영업 중인 점포로 한정 → 폐업점과의 직접 비교 차단 |
| **Temporal Decay (λ=0.75)** | 최근 관측값에 더 높은 가중치 부여 → 최근 경영 악화 신호 강조 |

### 2. 3-컴포넌트 신호 체계

```
RISK SCORE = 0.65 × 내부 신호 + 0.30 × 경쟁 신호 + 0.05 × 외부 신호
```

| 컴포넌트 | 포함 신호 | 가중치 |
|----------|-----------|--------|
| **내부 신호** | 매출 수준·추세, 거래 건수·추세, 객단가, 재방문율·추세, 유동/주거 고객 비중 | 65% |
| **경쟁 신호** | 업종·상권 내 상대 순위, 업종 대비 매출·추세 | 30% |
| **외부 신호** | 업종·상권 내 폐업 밀도 | 5% |

### 3. 피처 중요도 (Mann-Whitney Effect Size)

EDA 결과 **추세 피처가 수준 피처보다 2.5배 강한 분리력**을 보였습니다.

| 피처 | Effect Size | 해석 |
|------|-------------|------|
| f_sales_trend (매출 추세) | 0.247 | 최강 신호 |
| f_trx_trend (거래 추세) | 0.182 | 2위 |
| f_return_rate (재방문율) | 0.183 | 수준 피처 중 최강 |
| f_sales_lvl (매출 수준) | 0.171 | 추세보다 약함 |

> **인사이트**: 절대적 매출 수준보다 "최근 3개월간 방향"이 위기를 더 일찍 포착합니다.

### 4. 폐업 점포 위험 신호 궤적

사건 정렬 분석에서 폐업 점포는 폐업 4~3개월 전부터 위험 순위가 급등합니다.

```
T-12   T-9    T-6    T-3    T-0 (폐업)
 3.71 → 3.72 → 3.74 → 3.75 → 4.43   ← RC_M1_SAA 평균 버킷값
                              ↑ 급등 포착
```

## 모델 성능 및 통계 검증

단순 AUC 보고에 그치지 않고 3가지 통계 검증으로 타당성을 확인했습니다.

| 검증 방법 | 결과 | 의미 |
|-----------|------|------|
| **TUNED AUC** | 0.737 | BASE(0.668) 대비 +10.4% 향상 |
| **Permutation Test** | p < 0.001 (Z = 4.54σ) | 결과가 우연이 아님 |
| **Bootstrap 95% CI** | [0.653, 0.818] | 추정값 안정성 확인 |
| **전향적 검증 (2023→2024)** | AUC = 0.611, Lift@5% = 2.0x | 미래 데이터 없이도 예측 가능 |

> **전향적 검증**: 2023년 데이터만으로 2024년 폐업 15개 점포를 예측.  
> 미래 레이블을 전혀 사용하지 않은 가장 엄밀한 검증 방법.

## 위험 등급 및 맞춤 금융 서비스

EWS 점수를 4단계로 분류해 등급별 금융상품을 자동 연계합니다.

| 등급 | 임계값 | 점포 수 | 연계 금융상품 |
|------|--------|---------|---------------|
| 🔴 위험 | ≥ 85%ile | 476개 (15.2%) | 긴급경영안정자금 (소진공, 연 2.0%) |
| 🟡 경고 | ≥ 65%ile | 624개 (20.0%) | 소상공인 정책자금 (소진공, 연 3.5%) |
| 🔵 주의 | ≥ 40%ile | 782개 (25.0%) | EWS 연계 금리우대대출 (0.5%p 차감) |
| 🟢 정상 | < 40%ile | 1,245개 (39.8%) | 소상공인 성장자금 (우대금리) |

## 빠른 시작

### 1. 의존성 설치
```bash
pip install -r requirements.txt
```

### 2. 데이터 준비
`data/` 폴더에 대회 제공 원본 데이터를 위치시킵니다:
```
data/big_data_set1_f.csv   # 점포 마스터
data/big_data_set2_f.csv   # 월별 매출 (버킷 형식)
data/big_data_set3_f.csv   # 월별 고객 행동
```

### 3. 노트북 순서대로 실행
각 노트북은 이전 노트북의 `outputs/` 결과를 이어받습니다.
```
01 전처리 → 02 피처 → 03 EDA → 04 ML → 05 튜닝 → 06 검증
```

### 4. 대시보드 실행
```bash
cd app
streamlit run app_ews.py
```
